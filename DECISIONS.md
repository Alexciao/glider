# Decisions

One line of reasoning per decision. Newest at the bottom of each section.

## Platform & tooling
- **.NET 10 (LTS, SDK 10.0.404 locally)**: current LTS as of Nov 2026; `global.json` rolls forward within 10.0.
- **`.slnx` solution format**: default in .NET 10, smaller and merge-friendly.
- **xUnit v3 on Microsoft.Testing.Platform** (`global.json` `test.runner`): .NET 10 SDK no longer runs MTP-based tests through VSTest.
- **TypeScript 6.0.x, not 7.0**: typescript-eslint 8.x supports `<6.1`; TS 7 (native) would break linting.
- **Inter Variable (bundled via @fontsource-variable)**: excellent tabular numerals and Windows rendering, so no CDN.
- **Branch `main`**: the repo had no commits; renamed `master` to `main` to match the stated default.
- **Name stays "Glider"**: the user confirmed it (a "Spike" test app was a research agent's throwaway experiment, not a rename).

## IPC contract
- **C# records are the single source of truth; TS is generated by reflection** (`tools/Glider.ContractGen`): no third-party generator, handles nullability via `NullabilityInfoContext`, and a unit test fails when `contract.gen.ts` is stale.
- **Full `AppSnapshot` pushed on every change, plus a separate 10 Hz `progress` event**: the snapshot is a few KB, so whole-state replacement removes any patch/drift bugs; only progress is high-frequency.
- **Enums as camelCase strings via `CamelEnumConverter<T>`**: readable wire format and idiomatic TS unions; source-gen compatible.
- **System.Text.Json source generation (`GliderJsonContext`)**: avoids reflection-based serializer warm-up on startup.
- **Errors are data (`GliderError` with `FixAction`)**: every failure carries human copy and a one-click fix; all copy lives in `Errors.cs`.
- **Nullable fields are always present (`T | null`), never optional**: one shape on the wire, so there's no undefined/null ambiguity.

## Legendary & Epic integration
- **Sign-in captures `authorizationCode` from Epic's `id/api/redirect?clientId=34a02cf8…&responseType=code` JSON** (Legendary's documented flow) in a WebView2 window, then `auth --code`; this avoids Heroic's EGL-user-agent/localhost-redirect trick.
- **Signed-in check = `status --offline --json`; token refresh = online `status --json` in the background**: offline never crashes on network; online refresh happens during pre-warm.
- **Legendary's `egl_sync` config stays OFF; Glider writes EGL files itself** (mirroring `egl_export`): continuous egl-sync is a known crash and update-loop source, and owning the write lets us back up and write atomically.
- **Glider spawns the game itself from `launch --json`**: Legendary's `launch` exits immediately, so owning the process handle gives reliable running/closed tracking.
- **Run Legendary inside a Windows Job Object (kill-on-close)**: it's a PyInstaller two-process exe with multiprocessing children; tree-kill is the only reliable pause/cancel.
- **Exit codes are not trusted; outcomes come from parsed output**: most Legendary failures exit 0.
- **Stall watchdog + post-install verify**: Legendary retries failed chunks forever and doesn't abort on write failures.
- **Unattended install = `-y install Fortnite --base-path <p> --skip-sdl --skip-dlcs`**: `-y` alone still prompts for SDL packs.

## Host & packaging
- **Self-contained over the 60 MB installer target**: the spike measured 72 MB minimum self-contained (before the 17.6 MB Legendary exe); "user installs nothing" wins, so we minimize size (en-only satellites, no Windows SDK projection, no WinForms) and report the real number.
- **Plain `net10.0-windows` TFM (no `windows10.0.x` SDK projection)**: the projection adds a ~52 MB assembly to the self-contained output.
- **Toasts = `Shell_NotifyIcon` balloon notifications**: Windows 10/11 render them as native toasts, with no WinRT projection or stale toolkit packages.
- **Snap Layouts via a small child HWND over the HTML maximize button returning `HTMAXBUTTON`**: hit-testing in the top-level window doesn't work over WebView2 (verified in the spike).
- **HTML `app-region: drag` for the title bar** (`IsNonClientRegionSupportEnabled`): verified to move the WPF window.

## Process
- **Model budget (user constraint, 2026-11-12)**: exactly one Fable 5.2 task, spent on the screenshot-driven design/UX critique; all other subagents (incl. architecture/perf and security reviews, in place of GPT-6-Luna) run on Opus 5.5 high (xhigh only when essential).
- **MIT license for Glider's own code**: permissive and simple; Legendary stays a separate GPLv3 executable, so there's no linking concern.

## Mica / title bar fixes (v0.1.2, group B)
- **Root cause (Mica gray/white/broken)**: the host never modelled Windows' own Mica fallbacks (window inactive, "Transparency effects" off, Battery Saver); the page stayed translucent over DWM's flat colour, the host solid colours (#202020/#F3F3F3) did not match the CSS solid tokens (#0D0E11/#F6F7F8), and the backdrop was re-applied only for the system-theme change. Already correct and left alone: `AllowsTransparency` is false, WebView2 `DefaultBackgroundColor` is set in the controller options before creation, `Background`/`CompositionTarget.BackgroundColor` are transparent, margins -1, `SYSTEMBACKDROP_TYPE`=Mica, immersive dark mode.
- **Root cause (title bar)**: the Snap Layouts overlay rounded inset and width separately, so it drifted 1 px off the HTML maximize button at 125/175 % DPI. Native hit-testing (HTMAXBUTTON overlay, top-edge resize strip, WM_NCCALCSIZE maximize inset incl. auto-hide taskbar) was already sound; self-test confirms client rect == work area when maximized.
- **`BackdropPolicy.Decide` is the single Mica-vs-solid decision**; inactive keeps DWM Mica but the page goes opaque via `data-surface="solid"` (set by the host through ExecuteScript, and `&surface=solid` in the start URL), so the page matches DWM's flat fallback instead of tinting over it.
- **Host solid colours derived from the CSS tokens** (oklch to sRGB) and documented next to the constants; change both together.
- **Backdrop is re-applied on** WM_ACTIVATE (change only), WM_SETTINGCHANGE "ImmersiveColorSet" (also fires for transparency toggles), WM_THEMECHANGED, WM_DWMCOLORIZATIONCOLORCHANGED, WM_POWERBROADCAST status change, WM_DPICHANGED and maximize/restore; a light/dark flip first sets DWMSBT_NONE so DWM drops the old tint.
- **ChromeLogic.cs is compiled into Glider.Core.Tests via a link** (host has no test project; types are `public` only so xUnit can see them).
- **WebView2 crash recovery**: `HostRuntime.RecreateEnvironment()` before re-creating the controller; the old `EnvTask` was dead after a browser-process exit. Not exercised on a real crash.
- **Login window loading state**: WPF TextBlock under the hidden WebView2 child until first NavigationCompleted, 10 s safety reveal.
## Fix group C (EGL detection)
- **Detection logic was already drive-agnostic** (covered by existing fake-drive tests); the one real gap found was `File.ReadAllBytes` (FileShare.Read) failing while a running EGL has a manifest open for writing, which silently dropped the entry. Manifests are now read with FileShare.ReadWrite|Delete.
- **Quick scan probes known folders only** (`\Fortnite`, `\Epic Games\Fortnite`, `\Games\Fortnite`, `\Games\Epic Games\Fortnite`, `\Program Files[ (x86)]\Epic Games\Fortnite`) plus up to 64 direct children of `\Games`, `\Epic Games`, `\Games\Epic Games`, `\Program Files\Epic Games`; never recursive. Results are `CandidateSource.Manual` candidates merged into the EGL state until the next plain rescan.
- **Quick scan UI is a command-palette entry only**; no Settings button (Settings.tsx is being edited by the frontend branch).
- **Locate-folder also accepts a parent holding a differently named game folder and a folder inside the install** (up to 4 levels up); first matching child wins.
- **`InstallCandidate.Reason`** is a human-readable string (null when usable); frontend `candidateIssue` is unchanged.
- **Adopt in place and write-back needed no code change**: `legendary import` registers the folder without copying and write-back already backs up and writes atomically; new tests pin both on a non-C: path with spaces.
- FileLog: added FlushFileBuffers per drained batch for the 0-byte-while-open report; could not reproduce in a test (content was already flushed), so this targets NTFS stale-size metadata.
- Self-update: GithubSource on git remote Alexciao/glider, check 45 s after start then every 12 h, applies on exit (no forced restart), skipped for dev/portable/test runs; announced once via Notice event.
- Installer size (90.7 MB Setup, 154 MB publish) left as is: WPF forbids trimming, vpk 1.2.161 has no compression option and R2R/satellite flags are already set; <60 MB would need a framework-dependent build (product decision).
- Data dir (%LocalAppData%\Glider) shared with Velopack's root left as is: moving existing data or hooking uninstall to copy Legendary auth out is not a tiny safe change; revisit with an explicit data-location migration.
## v0.1.2 fixes: updates, repair, sizes (group D)
- **ROOT CAUSE, updates not recognized**: `UpdateAvailable` compared the latest version against `GameRecord.Version`, a copy refreshed only when a Glider job ends or at the startup EGL drift check, so a build installed outside a job (EGL, manual `legendary update`) left the record stale; every check now re-reads installed.json first (skipped while a job runs). Legendary's `info` already refreshes assets itself (`get_game(update_meta=True)`, core.py:515-520), so no `--force-refresh` is needed and `CheckAsync` already bypasses the 10-minute info cache. Not found and not changed: Epic's asset `build_version` vs the manifest's `build_version` format (could not verify against a real account); a launch that fails with "Game is out of date" still does not flip `UpdateAvailable`.
- **ROOT CAUSE, repair not fixing files**: every "repair" button (hero Repair, error fix, More menu, Settings) calls `game.verify`, which enqueued a verify-only job; `legendary verify` only reports (cli.py:1240-1346) and the `repair` command was never run for it. Verify jobs now run verify, `repair` (re-downloads only bad/missing files from the `.repair` file the verify just wrote), then a second verify; the job result carries `JobInfo.Verify` (files checked/bad/fixed/verified) and the notice text uses it.
- **Adopted EGL installs repair the same way**: `import` saves the `.egstore` manifest into Legendary's manifests dir (core.py:1890-1990), which `verify` needs; if it is missing, the existing repair fallback (`--repair-and-update`) restores files and the second verify confirms. Install tags are not set for adopted installs, so verify checks every manifest file and optional packs EGL never installed would be counted as missing.
- **Only Verify jobs got the new flow**: `JobKind.Repair` is not enqueued by any UI path, and install/update keep their existing verify then one automatic repair.
- **ROOT CAUSE, no on-disk size**: `GameState` only carried the manifest's `InstallSizeBytes`; nothing measured the folder. `InstalledSizeBytes` is a background walk (sum of file lengths, reparse points skipped), cancellable at shutdown, at least 30 s apart, cached in `cache/installed-size.json` keyed by folder+version (12 h trust unless a job just finished), and remeasured after install/update/repair/verify/move/adopt.
- **ROOT CAUSE, wrong download size for updates**: `DownloadSizeBytes` was always the manifest's full `download_size`, even when only an update delta would download. For an installed game with an update pending it is now Legendary's own analysis (`update --update-only` without `-y`, stopped at the "Download size" line; stdin is closed so it cannot proceed), once per installed/latest pair in the background, and null until known. Fresh installs keep the manifest `download_size` (per chosen install tags), never the install size.
- **`AppInfo.AvailableCdns` not done**: Legendary has no CDN list command (hosts only appear in a manifest's `base_urls` at runtime), so the list would be a hard-coded copy of the frontend's dropdown plus Settings UI wiring.
- **Playtime is tracked locally (v0.1.2)**: Legendary (checked `api/egs.py`, 0.20.x line; no playtime call) has no Epic server-side playtime support, and Epic's playtime service is not exposed through its API surface, so Core accumulates seconds from ProcessWatcher Running->Idle, flushes every 30 s and on exit into `state/game.json` (`PlaytimeSeconds`, `LastPlayedAt`); play outside Glider is not counted.
- **Hero buttons**: Play and More share `heroButtonBase/heroButtonTone` (PrimaryAction.tsx) as a 2 px-gapped split group, outer radius 16 (radius-xl), inner 6; More follows Play's emphasis colours.
- **Toasts moved top-right** (below the title bar) so they never cover the Library facts row at the bottom of the hero.
- **Light theme**: surface-1/2 are now white translucents (lighter than the page) instead of dark tints, so cards read as raised, not darker than the page.
- **`GameState.InstalledSizeBytes`** added (null from StateHub until Group D measures it); UI shows "Measuring…" while null.
## Epic sign-in: "Risposta errata. Aggiorna la pagina" + endless captchas (v0.1.2 report, Italian Windows)
- **Not reproduced (needs a real account); causes below are reasoned, not proven.** Most likely: the embedded page was loaded with the WebView2 controller `IsVisible=false` until the first NavigationCompleted, so Epic's captcha scripts initialised with `document.visibilityState == "hidden"`, no focus (`document.hasFocus()` false: the HWND child never received keyboard focus) and a stale window position (`NotifyParentWindowPositionChanged` was never called after a move, so `screenX/Y` drifted); hCaptcha/Arkose score those as a bot and the token is rejected after the 2FA step.
- **Login window is now visible, sized and focused from the first load** (no hidden state, no loading text: the WebView2 paints the theme background itself), `MoveFocus` on every activation, position notified on WM_MOVE/WM_WINDOWPOSCHANGED.
- **Checked and left alone**: no custom user agent, language follows the system (page renders Italian), `EnableTrackingPrevention=false` already lets captcha iframes keep their cookies, only two benign Edge-feature flags, the login profile ("GliderEpic", persistent) is wiped only on sign-out and is reused for every attempt, the redirect re-navigation only happens on the redirect URL (after login), not during the form/2FA steps.
- **Password-save bubble off** (`IsPasswordAutosaveEnabled` was true, plus autofill, accelerator keys, swipe and pinch off); Epic's own form is the only UI.
- **Window size**: client 520x780 DIPs (Epic's page still scrolls a little on the first step because of its social-login list), at most 90 % of the work area of the owner's monitor, centered on the owner and clamped on-screen, computed in physical pixels with `AdjustWindowRectExForDpi` at that monitor's DPI and re-applied once if the first placement crosses a DPI boundary.
- **Guaranteed fallback = Epic's page in the user's default browser + pasted code** (`auth.openBrowserLogin`, `auth.signInWithCode`): the real browser has Epic's trust and the user's sessions; the opened URL is the fixed `EpicSignIn.LoginUrl` (never a client-supplied URL, so no allowlist is needed), and the paste accepts the whole JSON page, a fragment or the bare code (`EpicSignIn.ParsePastedCode`) before the same `legendary auth --code` path.
- **Fallback entry points are deliberately quiet**: a text link under the onboarding sign-in button, under any `authFailed` sign-in error, and a command-palette entry; `authCancelled` stays silent (the user closing the window is their choice).
## Epic login window: identity audit (v0.1.4; `Glider.exe --login-audit=<dir>`)
- **Audit method**: the same JS probe + CDP `Network.requestWillBeSentExtraInfo` header capture ran in a plain WebView2, in the login window's configuration, and in a real headful Edge (throwaway profile, killed by PID); `audit-diff.txt` lists every difference. Epic's login page also loads its own `talon-service` (ecosec) fingerprinting and an invisible hCaptcha, so the page itself is the judge.
- **Differences found (WebView2 vs Edge 157)**: only the client hints (`sec-ch-ua` and `navigator.userAgentData` carried an extra "Microsoft Edge WebView2" brand in a different order, also on cross-site captcha iframes) and `window.chrome.webview` (present in WebView2, absent in Edge). UA string, languages, plugins, WebGL, hardware, cookies/storage, focus handling and Accept-Language were identical; Edge's `navigator.webdriver` was `true` only because it was started with `--remote-debugging-port` (WebView2: `false`), which also shows a driven-Edge sign-in would have looked automated to Epic.
- **Fix, login view only**: `Emulation.setUserAgentOverride` with the runtime's own brands minus WebView2 in Edge's order (`EdgeUserAgentMetadata`, probed on a synthetic in-memory https page because `userAgentData` needs a secure context), `window.chrome.webview` removed at document creation, web messages/host objects off, tracking prevention forced to None; re-audit shows no remaining identity difference except Edge's own `Prefer` request header (not set; no spoofing beyond matching the installed Edge).
- **Not proven**: that these were what Epic's captcha rejected (no account to test with); confidence low-to-moderate. The log now shows the next failure: login navigation starts and the status + path of Epic/hCaptcha/Arkose responses (no query, bodies, cookies or codes; failed/blocked requests with their error) go to the host log, and `app.getLogs` / Copy logs append its tail.
- **0.1.3 window behaviour is unchanged** (visible, focused, DPI-sized 520x780 clamped to 90 %, themed caption, no autofill/password prompt, no accelerator keys); verified with the self-test PrintWindow screenshot.
## Epic login: interactive diagnostic (`--login-debug`) and closed-window UX (v0.1.5)
- **`Glider.exe --login-debug=<dir> [--variant=current|plain|inprivate|noua]`**: real login window (main window stays hidden, own data dir `<dir>/data-<variant>`), flushed trail in `<dir>/login-debug-<variant>.log` + `<dir>/shots/`; network detail comes from CDP `Network.*` (not `WebResourceResponseReceived`) because only CDP gives per-request duration, request header NAMES and POST bodies for key names; error bodies (status >= 400, epicgames.com) are masked JSON cut to 600 chars (`LoginDebugRedaction`: `errorCode`/`errorMessage`/`numericErrorCode`/`messageVars` kept, credential-like keys, e-mails and token shapes hidden); the authorization code is never logged (only its length). Screenshots are taken when the visible error text changes and can show what was typed.
- **Variants**: `plain` = default WebView2 identity (no client-hint rewrite, no injected script, default tracking prevention); `noua` = current minus the `window.chrome.webview` removal script; `inprivate` = current + InPrivate controller.
- **A closed sign-in window is no longer silent**: `authCancelled` now shows a calm warning callout ("Sign-in was cancelled") with Copy diagnostic logs and the browser-code link, because Epic can show its own error inside the window and the user then just closes it.
- **`--variant=epicua` and `--no-cdp` (v0.1.5)**: `epicua` = current with Heroic's login UA (`Mozilla/5.0 (Windows NT 10.0; Win64; x64) EpicGamesLauncher`, set via `Settings.UserAgent` and one `Emulation.setUserAgentOverride`, no client-hint metadata); Legendary instead passes `EpicGamesLauncher/<egl version>` to pywebview and injects a `window.ue` launcher bridge (`requestexchangecodesignin`), which Epic's page treats as launcher mode. `--no-cdp` logs with managed events only (`WebResourceResponseReceived` also exposes the sent request, so header/JSON key names need no request filter; no durations, console or exceptions) and the client-hint probe uses `ExecuteScriptAsync` instead of `Runtime.evaluate`; the debug logger attaches no DevTools session in that mode. The login window also hands the page keyboard focus on WM_SETFOCUS, WM_ACTIVATE and after each navigation while active.
- **`--variant=legendary` replicates Legendary 0.21's webview login** (`webview_login.py`, `cli.py`): on Windows it first opens `https://www.epicgames.com/id/logout?productName=epic-games&redirectUrl=https://www.epicgames.com/id/login` with JS injection off (switched on once a load lands on a `logout` URL), UA `EpicGamesLauncher/<egl_version>` as the whole UA (core default `11.0.1-14907503+++Portal+Release-Live`), and after every later load injects `window.ue = {signinprompt:{requestexchangecodesignin, registersignincompletecallback}, common:{launchexternalurl}}`; the login page itself then hands over an **exchange code** through `requestexchangecodesignin` (no `redirectUrl`, no `authorizationCode` JSON). The replica uses `chrome.webview.postMessage` for the bridge, no DevTools logging, default tracking prevention, and logs only bridge names and the code length.
- **If the bridge route is what Epic accepts, Core needs an exchange-token sign-in**: Legendary does `core.auth_ex_token`, i.e. `legendary auth --token <exchange token>` (bundled 0.21.1 has `--code`, `--token`, `--sid`, `--import`, `--delete`, `--disable-webview`); Glider only has `SignInWithCodeAsync` (`--code`) today and is not wired for it yet.
- **All login windows reload on F5 / Ctrl+R / Ctrl+F5** (other accelerators stay off) **and once or twice automatically** (max 2 per window) when an `/id/api/login*` 400 response carries `errors.com.epicgames.accountportal.captcha_invalid` (only those 400 bodies are read); the reload and the URL it lands on are logged.
## Epic login: launcher mode is the fix (v0.1.5, supersedes the embedded-window entries above)
- **ROOT CAUSE (confirmed live, 4 variants)**: Epic's page only issues an accepted invisible token (talon-service / passive hCaptcha, the `captcha` value POSTed to `/id/api/login/mfa*`) in launcher mode: the `EpicGamesLauncher/<ver>` user agent plus the `window.ue` bridge that Legendary injects. `plain`, `current` (Edge client-hint rewrite) and `epicua` (Heroic's UA) all got `captcha_invalid` at the MFA steps; `legendary` completed password + captcha + 2FA. Edge-identity spoofing did not help and was removed (`EdgeUserAgentMetadata`, tracking-prevention override, `chrome.webview` removal, CDP diagnostics).
- **Production login window = the `legendary` variant**: logout URL first (lands on the login page, no bridge on that first load), UA `EpicGamesLauncher/11.0.1-14907503+++Portal+Release-Live` as the whole UA via `Settings.UserAgent` + one `Emulation.setUserAgentOverride` (no client hints), default tracking prevention, `window.ue` injected after every later load, managed-only host-log trace (status + path), F5/Ctrl+R reload and up-to-2 auto-reloads on `captcha_invalid`, plus the 0.1.3 native feel.
- **The result is an exchange code, not an authorization code**: the page calls `requestexchangecodesignin(code, param)`; `EpicSignIn.ParseExchangeCode` accepts a plain string, a quoted string or a JSON object, Core runs `legendary auth --token <code> --disable-webview` (same handling as `--code` before: argument 2 masked in the command log, `--token` added to `SecretRedactor`, the code never logged; it stays on Legendary's command line, the accepted risk noted in docs/fix-map.md).
- **Removed the browser/paste fallback** (RPCs `auth.openBrowserLogin`/`auth.signInWithCode`, dialog, link, palette entry, `--code`, authorization-code parsing): superseded by the launcher-mode window; the "Sign-in was cancelled" notice with Copy diagnostic logs stays.
- **Social-login popups** (Google, Facebook, Xbox, PlayStation...) open in a `PopupWindow` that shares the login window's chrome (themed caption, 480x640 DIP clamped to 90 % of the work area, centered on its owner, no taskbar entry, same settings/UA) and hosts the CoreWebView2 handed back via `NewWindowRequested` (deferral, `Handled`, `NewWindow`) so `window.opener`/postMessage work; only http(s) and `about:blank` may open or navigate there, `window.close()` closes it, closing the login window closes its popups (WPF owner). Self-test opens popups from the login page (`login.popup`); real social logins are manual.
## v0.2
- **Library from Legendary's files, never from its stdout**: `metadata/*.json` + `assets.json` + `installed.json` + `entitlements.json` are what Legendary itself reads at start-up, cost no 1.7 s spawn, and `list --json` stdout is huge (achievements).
- **Missing or torn Legendary file = unknown, never "not installed"**: Legendary rewrites them in place without locks; a torn installed.json must not flip every game to uninstalled, so the previous value (or Glider's record) wins.
- **`GameCatalog` is pure and `LibraryService` owns the only mutable map**: the mapping is testable against real catalog JSON, and one immutable map + revision makes "one delta per change" trivial to get right.
- **Library deltas are coalesced over 50 ms and `library.get` flushes first**: the UI never sees a revision gap between the full list and the next delta.
- **Cold start serves `cache/library.json` and rebuilds from files only when Legendary has a library on disk**: an empty or moved config dir must not wipe the cached grid before the first sync.
- **Art URLs are Epic's CDN URLs (cached v0.1 art via an index)**: the host has no lazy art handler yet (Phase 2); the CDN works in WebView2 today and the placeholder colour covers loading.
- **Entitlement-only DLC are synthesized from the base game's `dlcItemList`**: they have no metadata file but the user owns them (shown as NotInstallable).
- **Jobs keyed by (AppName, Kind)**: v0.1's per-kind idempotency would hand game B the job of game A.
- **A paused job blocks only its own game group (game + DLC)**: one stuck download must not freeze the whole library's queue.
- **"Move to top" never pre-empts the running job**: killing a download to start another costs its in-flight chunks; the user can pause it explicitly.
- **"Installed data lock" (exit 0) is retried inside the same run every 5 s**: it means another Legendary (EGL sync, a stray process) holds the lock; nothing else in the writer lane could run anyway.
- **WhilePlaying Pause stops only pausable writer jobs; uninstall/move/import still run**: they can't resume from a partial state, and they rarely compete with a game for bandwidth.
- **Effective download mode is policy only; process priorities go through `IResourcePolicy`**: Phase 2 owns the per-mode CPU/IO/memory plumbing; the default keeps v0.1's below-normal CPU for every mode.
- **Auth gate in the process runner, released at the first post-login line (or download/verify/JSON output, exit, 45 s)**: only the runner sees Legendary's lines; any output after login proves the token is written.
- **The launch lane always passes `--skip-version-check`**: Glider decides "up to date" from assets.json; Legendary's own check is an extra request that also rewrites assets.json.
- **Launch is refused only for that game's (or its base game's) unfinished writer jobs**: half-patched files must not run; another game's download never blocks Play.
- **Process tracking = spawned PID + descendants + profile names, adopted only if started with the session**: Fortnite's bootstrapper → EAC wrapper → shipping chain re-parents through the anti-cheat service (audit §0.3), and PID/name reuse by older processes must not count.
- **A session ends after 5 s with nothing tracked; a launch fails after 10 s with nothing tracked (or the timeout with nothing alive)**: stubs exit and respawn the game within seconds; a still-alive process past the timeout is tracked rather than reported as a failed launch.
- **Generic EAC = an `EasyAntiCheat` folder with `Settings.json` and a safe product id**: easy.ac's documented layout; no product id means nothing is run elevated.
- **DLC are their own writer jobs and the base always gets `--skip-dlcs`**: Legendary's `--with-dlcs` recursion inherits tags and can `exit(0)` mid-way (L§3).
- **Explicit components = `--install-tag` per tag plus `""`; none = `--skip-sdl`**: untagged files are always part of a game, and Legendary deletes deselected tags' files.
- **Imports are jobs with an outcome (Imported / NeedsRepair + a queued Verify / Failed)**: bulk EGL import needs per-game progress and results; v0.1 imported inside the RPC.
- **EGL scans every game `.item` (DLC excluded) and skips `UE_*` engine entries**: the whole library is importable; engines are not games.
- **Per-game settings (launch args, auto-update, launch mode…) live in `games.json`, never in Legendary's config.ini**: Legendary overwrites config.ini at exit and Glider spawns the game itself.
- **`settings.json` keeps the field-by-field tolerant reader and gains `schemaVersion`**: v0.1 files and future fields load without resetting everything.
- **Migration writes `state/schema.json` last and backs everything up first**: a crash or failure mid-way is simply retried next start; v0.1-only files (game.json, window.json, art.json, .bak) are never modified, and the files v2 reuses (settings, jobs, onboarding, installed-size) are rewritten only after their byte copy is in `backups/migration`.
- **jobs.json v1 is converted, not reinterpreted**: the v2 reader then only knows one shape; the PascalCase `step` stays accepted by `JobStepConverter`.
- **Phase 2 RPCs answer with empty states or "Not available yet"**: the contract is complete for the frontend now, and each stub lives in the service class its feature will replace.
