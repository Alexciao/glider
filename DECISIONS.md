# Decisions

One line of reasoning per decision. Newest at the bottom of each section.

## Platform & tooling
- **.NET 10 (LTS, SDK 10.0.404 locally)**: current LTS as of Nov 2026; `global.json` rolls forward within 10.0.
- **`.slnx` solution format**: default in .NET 10, smaller and merge-friendly.
- **xUnit v3 on Microsoft.Testing.Platform** (`global.json` `test.runner`): .NET 10 SDK no longer runs MTP-based tests through VSTest.
- **TypeScript 6.0.x, not 7.0**: typescript-eslint 8.x supports `<6.1`; TS 7 (native) would break linting.
- **Inter Variable (bundled via @fontsource-variable)**: excellent tabular numerals and Windows rendering, so no CDN.
- **Branch `main`**: the repo had no commits; renamed `master` to `main` to match the stated default.
- **Name stays "Glider"**: the user confirmed it (a "Spike" test app was a research agent's throwaway experiment, not a rename).

## IPC contract
- **C# records are the single source of truth; TS is generated by reflection** (`tools/Glider.ContractGen`): no third-party generator, handles nullability via `NullabilityInfoContext`, and a unit test fails when `contract.gen.ts` is stale.
- **Full `AppSnapshot` pushed on every change, plus a separate 10 Hz `progress` event**: the snapshot is a few KB, so whole-state replacement removes any patch/drift bugs; only progress is high-frequency.
- **Enums as camelCase strings via `CamelEnumConverter<T>`**: readable wire format and idiomatic TS unions; source-gen compatible.
- **System.Text.Json source generation (`GliderJsonContext`)**: avoids reflection-based serializer warm-up on startup.
- **Errors are data (`GliderError` with `FixAction`)**: every failure carries human copy and a one-click fix; all copy lives in `Errors.cs`.
- **Nullable fields are always present (`T | null`), never optional**: one shape on the wire, so there's no undefined/null ambiguity.

## Legendary & Epic integration
- **Sign-in captures `authorizationCode` from Epic's `id/api/redirect?clientId=34a02cf8…&responseType=code` JSON** (Legendary's documented flow) in a WebView2 window, then `auth --code`; this avoids Heroic's EGL-user-agent/localhost-redirect trick.
- **Signed-in check = `status --offline --json`; token refresh = online `status --json` in the background**: offline never crashes on network; online refresh happens during pre-warm.
- **Legendary's `egl_sync` config stays OFF; Glider writes EGL files itself** (mirroring `egl_export`): continuous egl-sync is a known crash and update-loop source, and owning the write lets us back up and write atomically.
- **Glider spawns the game itself from `launch --json`**: Legendary's `launch` exits immediately, so owning the process handle gives reliable running/closed tracking.
- **Run Legendary inside a Windows Job Object (kill-on-close)**: it's a PyInstaller two-process exe with multiprocessing children; tree-kill is the only reliable pause/cancel.
- **Exit codes are not trusted; outcomes come from parsed output**: most Legendary failures exit 0.
- **Stall watchdog + post-install verify**: Legendary retries failed chunks forever and doesn't abort on write failures.
- **Unattended install = `-y install Fortnite --base-path <p> --skip-sdl --skip-dlcs`**: `-y` alone still prompts for SDL packs.

## Host & packaging
- **Self-contained over the 60 MB installer target**: the spike measured 72 MB minimum self-contained (before the 17.6 MB Legendary exe); "user installs nothing" wins, so we minimize size (en-only satellites, no Windows SDK projection, no WinForms) and report the real number.
- **Plain `net10.0-windows` TFM (no `windows10.0.x` SDK projection)**: the projection adds a ~52 MB assembly to the self-contained output.
- **Toasts = `Shell_NotifyIcon` balloon notifications**: Windows 10/11 render them as native toasts, with no WinRT projection or stale toolkit packages.
- **Snap Layouts via a small child HWND over the HTML maximize button returning `HTMAXBUTTON`**: hit-testing in the top-level window doesn't work over WebView2 (verified in the spike).
- **HTML `app-region: drag` for the title bar** (`IsNonClientRegionSupportEnabled`): verified to move the WPF window.

## Process
- **Model budget (user constraint, 2026-11-12)**: exactly one Fable 5.2 task, spent on the screenshot-driven design/UX critique; all other subagents (incl. architecture/perf and security reviews, in place of GPT-6-Luna) run on Opus 5.5 high (xhigh only when essential).
- **MIT license for Glider's own code**: permissive and simple; Legendary stays a separate GPLv3 executable, so there's no linking concern.

## Mica / title bar fixes (v0.1.2, group B)
- **Root cause (Mica gray/white/broken)**: the host never modelled Windows' own Mica fallbacks (window inactive, "Transparency effects" off, Battery Saver); the page stayed translucent over DWM's flat colour, the host solid colours (#202020/#F3F3F3) did not match the CSS solid tokens (#0D0E11/#F6F7F8), and the backdrop was re-applied only for the system-theme change. Already correct and left alone: `AllowsTransparency` is false, WebView2 `DefaultBackgroundColor` is set in the controller options before creation, `Background`/`CompositionTarget.BackgroundColor` are transparent, margins -1, `SYSTEMBACKDROP_TYPE`=Mica, immersive dark mode.
- **Root cause (title bar)**: the Snap Layouts overlay rounded inset and width separately, so it drifted 1 px off the HTML maximize button at 125/175 % DPI. Native hit-testing (HTMAXBUTTON overlay, top-edge resize strip, WM_NCCALCSIZE maximize inset incl. auto-hide taskbar) was already sound; self-test confirms client rect == work area when maximized.
- **`BackdropPolicy.Decide` is the single Mica-vs-solid decision**; inactive keeps DWM Mica but the page goes opaque via `data-surface="solid"` (set by the host through ExecuteScript, and `&surface=solid` in the start URL), so the page matches DWM's flat fallback instead of tinting over it.
- **Host solid colours derived from the CSS tokens** (oklch to sRGB) and documented next to the constants; change both together.
- **Backdrop is re-applied on** WM_ACTIVATE (change only), WM_SETTINGCHANGE "ImmersiveColorSet" (also fires for transparency toggles), WM_THEMECHANGED, WM_DWMCOLORIZATIONCOLORCHANGED, WM_POWERBROADCAST status change, WM_DPICHANGED and maximize/restore; a light/dark flip first sets DWMSBT_NONE so DWM drops the old tint.
- **ChromeLogic.cs is compiled into Glider.Core.Tests via a link** (host has no test project; types are `public` only so xUnit can see them).
- **WebView2 crash recovery**: `HostRuntime.RecreateEnvironment()` before re-creating the controller; the old `EnvTask` was dead after a browser-process exit. Not exercised on a real crash.
- **Login window loading state**: WPF TextBlock under the hidden WebView2 child until first NavigationCompleted, 10 s safety reveal.
## Fix group C (EGL detection)
- **Detection logic was already drive-agnostic** (covered by existing fake-drive tests); the one real gap found was `File.ReadAllBytes` (FileShare.Read) failing while a running EGL has a manifest open for writing, which silently dropped the entry. Manifests are now read with FileShare.ReadWrite|Delete.
- **Quick scan probes known folders only** (`\Fortnite`, `\Epic Games\Fortnite`, `\Games\Fortnite`, `\Games\Epic Games\Fortnite`, `\Program Files[ (x86)]\Epic Games\Fortnite`) plus up to 64 direct children of `\Games`, `\Epic Games`, `\Games\Epic Games`, `\Program Files\Epic Games`; never recursive. Results are `CandidateSource.Manual` candidates merged into the EGL state until the next plain rescan.
- **Quick scan UI is a command-palette entry only**; no Settings button (Settings.tsx is being edited by the frontend branch).
- **Locate-folder also accepts a parent holding a differently named game folder and a folder inside the install** (up to 4 levels up); first matching child wins.
- **`InstallCandidate.Reason`** is a human-readable string (null when usable); frontend `candidateIssue` is unchanged.
- **Adopt in place and write-back needed no code change**: `legendary import` registers the folder without copying and write-back already backs up and writes atomically; new tests pin both on a non-C: path with spaces.
- FileLog: added FlushFileBuffers per drained batch for the 0-byte-while-open report; could not reproduce in a test (content was already flushed), so this targets NTFS stale-size metadata.
- Self-update: GithubSource on git remote Alexciao/glider, check 45 s after start then every 12 h, applies on exit (no forced restart), skipped for dev/portable/test runs; announced once via Notice event.
- Installer size (90.7 MB Setup, 154 MB publish) left as is: WPF forbids trimming, vpk 1.2.161 has no compression option and R2R/satellite flags are already set; <60 MB would need a framework-dependent build (product decision).
- Data dir (%LocalAppData%\Glider) shared with Velopack's root left as is: moving existing data or hooking uninstall to copy Legendary auth out is not a tiny safe change; revisit with an explicit data-location migration.
## v0.1.2 fixes: updates, repair, sizes (group D)
- **ROOT CAUSE, updates not recognized**: `UpdateAvailable` compared the latest version against `GameRecord.Version`, a copy refreshed only when a Glider job ends or at the startup EGL drift check, so a build installed outside a job (EGL, manual `legendary update`) left the record stale; every check now re-reads installed.json first (skipped while a job runs). Legendary's `info` already refreshes assets itself (`get_game(update_meta=True)`, core.py:515-520), so no `--force-refresh` is needed and `CheckAsync` already bypasses the 10-minute info cache. Not found and not changed: Epic's asset `build_version` vs the manifest's `build_version` format (could not verify against a real account); a launch that fails with "Game is out of date" still does not flip `UpdateAvailable`.
- **ROOT CAUSE, repair not fixing files**: every "repair" button (hero Repair, error fix, More menu, Settings) calls `game.verify`, which enqueued a verify-only job; `legendary verify` only reports (cli.py:1240-1346) and the `repair` command was never run for it. Verify jobs now run verify, `repair` (re-downloads only bad/missing files from the `.repair` file the verify just wrote), then a second verify; the job result carries `JobInfo.Verify` (files checked/bad/fixed/verified) and the notice text uses it.
- **Adopted EGL installs repair the same way**: `import` saves the `.egstore` manifest into Legendary's manifests dir (core.py:1890-1990), which `verify` needs; if it is missing, the existing repair fallback (`--repair-and-update`) restores files and the second verify confirms. Install tags are not set for adopted installs, so verify checks every manifest file and optional packs EGL never installed would be counted as missing.
- **Only Verify jobs got the new flow**: `JobKind.Repair` is not enqueued by any UI path, and install/update keep their existing verify then one automatic repair.
- **ROOT CAUSE, no on-disk size**: `GameState` only carried the manifest's `InstallSizeBytes`; nothing measured the folder. `InstalledSizeBytes` is a background walk (sum of file lengths, reparse points skipped), cancellable at shutdown, at least 30 s apart, cached in `cache/installed-size.json` keyed by folder+version (12 h trust unless a job just finished), and remeasured after install/update/repair/verify/move/adopt.
- **ROOT CAUSE, wrong download size for updates**: `DownloadSizeBytes` was always the manifest's full `download_size`, even when only an update delta would download. For an installed game with an update pending it is now Legendary's own analysis (`update --update-only` without `-y`, stopped at the "Download size" line; stdin is closed so it cannot proceed), once per installed/latest pair in the background, and null until known. Fresh installs keep the manifest `download_size` (per chosen install tags), never the install size.
- **`AppInfo.AvailableCdns` not done**: Legendary has no CDN list command (hosts only appear in a manifest's `base_urls` at runtime), so the list would be a hard-coded copy of the frontend's dropdown plus Settings UI wiring.
- **Playtime is tracked locally (v0.1.2)**: Legendary (checked `api/egs.py`, 0.20.x line; no playtime call) has no Epic server-side playtime support, and Epic's playtime service is not exposed through its API surface, so Core accumulates seconds from ProcessWatcher Running->Idle, flushes every 30 s and on exit into `state/game.json` (`PlaytimeSeconds`, `LastPlayedAt`); play outside Glider is not counted.
- **Hero buttons**: Play and More share `heroButtonBase/heroButtonTone` (PrimaryAction.tsx) as a 2 px-gapped split group, outer radius 16 (radius-xl), inner 6; More follows Play's emphasis colours.
- **Toasts moved top-right** (below the title bar) so they never cover the Library facts row at the bottom of the hero.
- **Light theme**: surface-1/2 are now white translucents (lighter than the page) instead of dark tints, so cards read as raised, not darker than the page.
- **`GameState.InstalledSizeBytes`** added (null from StateHub until Group D measures it); UI shows "Measuring…" while null.
## Epic sign-in: "Risposta errata. Aggiorna la pagina" + endless captchas (v0.1.2 report, Italian Windows)
- **Not reproduced (needs a real account); causes below are reasoned, not proven.** Most likely: the embedded page was loaded with the WebView2 controller `IsVisible=false` until the first NavigationCompleted, so Epic's captcha scripts initialised with `document.visibilityState == "hidden"`, no focus (`document.hasFocus()` false: the HWND child never received keyboard focus) and a stale window position (`NotifyParentWindowPositionChanged` was never called after a move, so `screenX/Y` drifted); hCaptcha/Arkose score those as a bot and the token is rejected after the 2FA step.
- **Login window is now visible, sized and focused from the first load** (no hidden state, no loading text: the WebView2 paints the theme background itself), `MoveFocus` on every activation, position notified on WM_MOVE/WM_WINDOWPOSCHANGED.
- **Checked and left alone**: no custom user agent, language follows the system (page renders Italian), `EnableTrackingPrevention=false` already lets captcha iframes keep their cookies, only two benign Edge-feature flags, the login profile ("GliderEpic", persistent) is wiped only on sign-out and is reused for every attempt, the redirect re-navigation only happens on the redirect URL (after login), not during the form/2FA steps.
- **Password-save bubble off** (`IsPasswordAutosaveEnabled` was true, plus autofill, accelerator keys, swipe and pinch off); Epic's own form is the only UI.
- **Window size**: client 520x780 DIPs (Epic's page still scrolls a little on the first step because of its social-login list), at most 90 % of the work area of the owner's monitor, centered on the owner and clamped on-screen, computed in physical pixels with `AdjustWindowRectExForDpi` at that monitor's DPI and re-applied once if the first placement crosses a DPI boundary.
- **Guaranteed fallback = Epic's page in the user's default browser + pasted code** (`auth.openBrowserLogin`, `auth.signInWithCode`): the real browser has Epic's trust and the user's sessions; the opened URL is the fixed `EpicSignIn.LoginUrl` (never a client-supplied URL, so no allowlist is needed), and the paste accepts the whole JSON page, a fragment or the bare code (`EpicSignIn.ParsePastedCode`) before the same `legendary auth --code` path.
- **Fallback entry points are deliberately quiet**: a text link under the onboarding sign-in button, under any `authFailed` sign-in error, and a command-palette entry; `authCancelled` stays silent (the user closing the window is their choice).
## Epic login window: identity audit (v0.1.4; `Glider.exe --login-audit=<dir>`)
- **Audit method**: the same JS probe + CDP `Network.requestWillBeSentExtraInfo` header capture ran in a plain WebView2, in the login window's configuration, and in a real headful Edge (throwaway profile, killed by PID); `audit-diff.txt` lists every difference. Epic's login page also loads its own `talon-service` (ecosec) fingerprinting and an invisible hCaptcha, so the page itself is the judge.
- **Differences found (WebView2 vs Edge 157)**: only the client hints (`sec-ch-ua` and `navigator.userAgentData` carried an extra "Microsoft Edge WebView2" brand in a different order, also on cross-site captcha iframes) and `window.chrome.webview` (present in WebView2, absent in Edge). UA string, languages, plugins, WebGL, hardware, cookies/storage, focus handling and Accept-Language were identical; Edge's `navigator.webdriver` was `true` only because it was started with `--remote-debugging-port` (WebView2: `false`), which also shows a driven-Edge sign-in would have looked automated to Epic.
- **Fix, login view only**: `Emulation.setUserAgentOverride` with the runtime's own brands minus WebView2 in Edge's order (`EdgeUserAgentMetadata`, probed on a synthetic in-memory https page because `userAgentData` needs a secure context), `window.chrome.webview` removed at document creation, web messages/host objects off, tracking prevention forced to None; re-audit shows no remaining identity difference except Edge's own `Prefer` request header (not set; no spoofing beyond matching the installed Edge).
- **Not proven**: that these were what Epic's captcha rejected (no account to test with); confidence low-to-moderate. The log now shows the next failure: login navigation starts and the status + path of Epic/hCaptcha/Arkose responses (no query, bodies, cookies or codes; failed/blocked requests with their error) go to the host log, and `app.getLogs` / Copy logs append its tail.
- **0.1.3 window behaviour is unchanged** (visible, focused, DPI-sized 520x780 clamped to 90 %, themed caption, no autofill/password prompt, no accelerator keys); verified with the self-test PrintWindow screenshot.
## Epic login: interactive diagnostic (`--login-debug`) and closed-window UX (v0.1.5)
- **`Glider.exe --login-debug=<dir> [--variant=current|plain|inprivate|noua]`**: real login window (main window stays hidden, own data dir `<dir>/data-<variant>`), flushed trail in `<dir>/login-debug-<variant>.log` + `<dir>/shots/`; network detail comes from CDP `Network.*` (not `WebResourceResponseReceived`) because only CDP gives per-request duration, request header NAMES and POST bodies for key names; error bodies (status >= 400, epicgames.com) are masked JSON cut to 600 chars (`LoginDebugRedaction`: `errorCode`/`errorMessage`/`numericErrorCode`/`messageVars` kept, credential-like keys, e-mails and token shapes hidden); the authorization code is never logged (only its length). Screenshots are taken when the visible error text changes and can show what was typed.
- **Variants**: `plain` = default WebView2 identity (no client-hint rewrite, no injected script, default tracking prevention); `noua` = current minus the `window.chrome.webview` removal script; `inprivate` = current + InPrivate controller.
- **A closed sign-in window is no longer silent**: `authCancelled` now shows a calm warning callout ("Sign-in was cancelled") with Copy diagnostic logs and the browser-code link, because Epic can show its own error inside the window and the user then just closes it.
- **`--variant=epicua` and `--no-cdp` (v0.1.5)**: `epicua` = current with Heroic's login UA (`Mozilla/5.0 (Windows NT 10.0; Win64; x64) EpicGamesLauncher`, set via `Settings.UserAgent` and one `Emulation.setUserAgentOverride`, no client-hint metadata); Legendary instead passes `EpicGamesLauncher/<egl version>` to pywebview and injects a `window.ue` launcher bridge (`requestexchangecodesignin`), which Epic's page treats as launcher mode. `--no-cdp` logs with managed events only (`WebResourceResponseReceived` also exposes the sent request, so header/JSON key names need no request filter; no durations, console or exceptions) and the client-hint probe uses `ExecuteScriptAsync` instead of `Runtime.evaluate`; the debug logger attaches no DevTools session in that mode. The login window also hands the page keyboard focus on WM_SETFOCUS, WM_ACTIVATE and after each navigation while active.
- **`--variant=legendary` replicates Legendary 0.21's webview login** (`webview_login.py`, `cli.py`): on Windows it first opens `https://www.epicgames.com/id/logout?productName=epic-games&redirectUrl=https://www.epicgames.com/id/login` with JS injection off (switched on once a load lands on a `logout` URL), UA `EpicGamesLauncher/<egl_version>` as the whole UA (core default `11.0.1-14907503+++Portal+Release-Live`), and after every later load injects `window.ue = {signinprompt:{requestexchangecodesignin, registersignincompletecallback}, common:{launchexternalurl}}`; the login page itself then hands over an **exchange code** through `requestexchangecodesignin` (no `redirectUrl`, no `authorizationCode` JSON). The replica uses `chrome.webview.postMessage` for the bridge, no DevTools logging, default tracking prevention, and logs only bridge names and the code length.
- **If the bridge route is what Epic accepts, Core needs an exchange-token sign-in**: Legendary does `core.auth_ex_token`, i.e. `legendary auth --token <exchange token>` (bundled 0.21.1 has `--code`, `--token`, `--sid`, `--import`, `--delete`, `--disable-webview`); Glider only has `SignInWithCodeAsync` (`--code`) today and is not wired for it yet.
- **All login windows reload on F5 / Ctrl+R / Ctrl+F5** (other accelerators stay off) **and once or twice automatically** (max 2 per window) when an `/id/api/login*` 400 response carries `errors.com.epicgames.accountportal.captcha_invalid` (only those 400 bodies are read); the reload and the URL it lands on are logged.
## Epic login: launcher mode is the fix (v0.1.5, supersedes the embedded-window entries above)
- **ROOT CAUSE (confirmed live, 4 variants)**: Epic's page only issues an accepted invisible token (talon-service / passive hCaptcha, the `captcha` value POSTed to `/id/api/login/mfa*`) in launcher mode: the `EpicGamesLauncher/<ver>` user agent plus the `window.ue` bridge that Legendary injects. `plain`, `current` (Edge client-hint rewrite) and `epicua` (Heroic's UA) all got `captcha_invalid` at the MFA steps; `legendary` completed password + captcha + 2FA. Edge-identity spoofing did not help and was removed (`EdgeUserAgentMetadata`, tracking-prevention override, `chrome.webview` removal, CDP diagnostics).
- **Production login window = the `legendary` variant**: logout URL first (lands on the login page, no bridge on that first load), UA `EpicGamesLauncher/11.0.1-14907503+++Portal+Release-Live` as the whole UA via `Settings.UserAgent` + one `Emulation.setUserAgentOverride` (no client hints), default tracking prevention, `window.ue` injected after every later load, managed-only host-log trace (status + path), F5/Ctrl+R reload and up-to-2 auto-reloads on `captcha_invalid`, plus the 0.1.3 native feel.
- **The result is an exchange code, not an authorization code**: the page calls `requestexchangecodesignin(code, param)`; `EpicSignIn.ParseExchangeCode` accepts a plain string, a quoted string or a JSON object, Core runs `legendary auth --token <code> --disable-webview` (same handling as `--code` before: argument 2 masked in the command log, `--token` added to `SecretRedactor`, the code never logged; it stays on Legendary's command line, the accepted risk noted in docs/fix-map.md).
- **Removed the browser/paste fallback** (RPCs `auth.openBrowserLogin`/`auth.signInWithCode`, dialog, link, palette entry, `--code`, authorization-code parsing): superseded by the launcher-mode window; the "Sign-in was cancelled" notice with Copy diagnostic logs stays.
- **Social-login popups** (Google, Facebook, Xbox, PlayStation...) open in a `PopupWindow` that shares the login window's chrome (themed caption, 480x640 DIP clamped to 90 % of the work area, centered on its owner, no taskbar entry, same settings/UA) and hosts the CoreWebView2 handed back via `NewWindowRequested` (deferral, `Handled`, `NewWindow`) so `window.opener`/postMessage work; only http(s) and `about:blank` may open or navigate there, `window.close()` closes it, closing the login window closes its popups (WPF owner). Self-test opens popups from the login page (`login.popup`); real social logins are manual.
## v0.2
- **Library from Legendary's files, never from its stdout**: `metadata/*.json` + `assets.json` + `installed.json` + `entitlements.json` are what Legendary itself reads at start-up, cost no 1.7 s spawn, and `list --json` stdout is huge (achievements).
- **Missing or torn Legendary file = unknown, never "not installed"**: Legendary rewrites them in place without locks; a torn installed.json must not flip every game to uninstalled, so the previous value (or Glider's record) wins.
- **`GameCatalog` is pure and `LibraryService` owns the only mutable map**: the mapping is testable against real catalog JSON, and one immutable map + revision makes "one delta per change" trivial to get right.
- **Library deltas are coalesced over 50 ms and `library.get` flushes first**: the UI never sees a revision gap between the full list and the next delta.
- **Cold start serves `cache/library.json` and rebuilds from files only when Legendary has a library on disk**: an empty or moved config dir must not wipe the cached grid before the first sync.
- **Art URLs are Epic's CDN URLs (cached v0.1 art via an index)**: the host has no lazy art handler yet (Phase 2); the CDN works in WebView2 today and the placeholder colour covers loading.
- **Entitlement-only DLC are synthesized from the base game's `dlcItemList`**: they have no metadata file but the user owns them (shown as NotInstallable).
- **Jobs keyed by (AppName, Kind)**: v0.1's per-kind idempotency would hand game B the job of game A.
- **A paused job blocks only its own game group (game + DLC)**: one stuck download must not freeze the whole library's queue.
- **"Move to top" never pre-empts the running job**: killing a download to start another costs its in-flight chunks; the user can pause it explicitly.
- **"Installed data lock" (exit 0) is retried inside the same run every 5 s**: it means another Legendary (EGL sync, a stray process) holds the lock; nothing else in the writer lane could run anyway.
- **WhilePlaying Pause stops only pausable writer jobs; uninstall/move/import still run**: they can't resume from a partial state, and they rarely compete with a game for bandwidth.
- **Effective download mode is policy only; process priorities go through `IResourcePolicy`**: Phase 2 owns the per-mode CPU/IO/memory plumbing; the default keeps v0.1's below-normal CPU for every mode.
- **Auth gate in the process runner, released at the first post-login line (or download/verify/JSON output, exit, 45 s)**: only the runner sees Legendary's lines; any output after login proves the token is written.
- **The launch lane always passes `--skip-version-check`**: Glider decides "up to date" from assets.json; Legendary's own check is an extra request that also rewrites assets.json.
- **Launch is refused only for that game's (or its base game's) unfinished writer jobs**: half-patched files must not run; another game's download never blocks Play.
- **Process tracking = spawned PID + descendants + profile names, adopted only if started with the session**: Fortnite's bootstrapper → EAC wrapper → shipping chain re-parents through the anti-cheat service (audit §0.3), and PID/name reuse by older processes must not count.
- **A session ends after 5 s with nothing tracked; a launch fails after 10 s with nothing tracked (or the timeout with nothing alive)**: stubs exit and respawn the game within seconds; a still-alive process past the timeout is tracked rather than reported as a failed launch.
- **Generic EAC = an `EasyAntiCheat` folder with `Settings.json` and a safe product id**: easy.ac's documented layout; no product id means nothing is run elevated.
- **DLC are their own writer jobs and the base always gets `--skip-dlcs`**: Legendary's `--with-dlcs` recursion inherits tags and can `exit(0)` mid-way (L§3).
- **Explicit components = `--install-tag` per tag plus `""`; none = `--skip-sdl`**: untagged files are always part of a game, and Legendary deletes deselected tags' files.
- **Imports are jobs with an outcome (Imported / NeedsRepair + a queued Verify / Failed)**: bulk EGL import needs per-game progress and results; v0.1 imported inside the RPC.
- **EGL scans every game `.item` (DLC excluded) and skips `UE_*` engine entries**: the whole library is importable; engines are not games.
- **Per-game settings (launch args, auto-update, launch mode…) live in `games.json`, never in Legendary's config.ini**: Legendary overwrites config.ini at exit and Glider spawns the game itself.
- **`settings.json` keeps the field-by-field tolerant reader and gains `schemaVersion`**: v0.1 files and future fields load without resetting everything.
- **Migration writes `state/schema.json` last and backs everything up first**: a crash or failure mid-way is simply retried next start; v0.1-only files (game.json, window.json, art.json, .bak) are never modified, and the files v2 reuses (settings, jobs, onboarding, installed-size) are rewritten only after their byte copy is in `backups/migration`.
- **jobs.json v1 is converted, not reinterpreted**: the v2 reader then only knows one shape; the PascalCase `step` stays accepted by `JobStepConverter`.
- **Phase 2 RPCs answer with empty states or "Not available yet"**: the contract is complete for the frontend now, and each stub lives in the service class its feature will replace.
- **Shortcuts launch through Glider with `--launch <app>`, not through `glider://`**: the link works without any protocol registration and uses the same strict app-name validation; a running Glider launches instantly via the single-instance pipe, a cold start launches hidden.
- **Shortcut files are matched by their arguments, never by name alone**: Epic's launcher names its shortcuts after the title; Glider writes `Title (Glider).lnk` instead of overwriting, and only deletes links whose arguments are `--launch <app>`.
- **Shortcut repair never guesses**: a missing link the user deleted clears the flag, and nothing is removed while the library is unknown (no record and Legendary's files not read yet).
- **Links are an allow-list parser in Core (`GliderLinkParser`, `EpicLauncherUri`)**: identifiers only, one percent-decode then validate, query ignored, no paths; a web page cannot inject launch arguments, and `install` links only open the install dialog.
- **Refused or unsupported links still show the main window**: a cold start from a bad link must not leave a hidden process.
- **Registry and .lnk access sit behind `IRegistryAccess` / `IShellLinks`**: Core is cross-platform and tests never touch the real registry or Desktop; the Windows adapters are compiled into the tests and checked against a temp folder and a throwaway `HKCU\Software\GliderTests\<guid>` key.
- **The Epic link handler snapshots the whole per-user key before taking over and restores exactly that**: typed values and subkeys go to `state/protocol-backup.json`; a key written by someone else since is left alone, and a failed backup aborts the takeover.
- **`glider://` is registered by Velopack hooks and at start only for installed builds**: portable and dev runs leave HKCU alone unless the user turns the Epic handler on.
- **Tray menu = pure model (`TrayMenuModel`) built from the cached snapshot + one pass over the library when it opens**: the tooltip follows `state`/`progress` events through a 1 s trailing timer; the UI thread only draws.
- **Cloud saves decide by a 3-way check against `state/saves.json`, not by comparing clocks**: Legendary's newest-mtime-wins can overwrite a newer save (skew, touched logs, DST); "did local change / did the cloud change since the last sync" needs no cross-machine clock. Both changed, or a first sync with both sides present and not within Legendary's 60 s window, is a Conflict that Auto never resolves.
- **Local change = filtered file set/size/SHA-256, not mtime**: the game's include/exclude lists apply (a log written on every start is not a change) and a touched-but-identical file is unchanged.
- **Cloud change = a new manifest name, or the newest one gone**: manifests are append-only, so this ignores `clean-saves` of old ones and any manifest ordering/clock problem.
- **Every overwrite is preceded by a verified local backup, and a failed download is restored from it**: Legendary deletes the local files before fetching and prints "Successfully completed" even when the fetch failed, so success is proven on disk (files carrying a manifest's time), not from the log.
- **Uploads are verified by re-listing**: Legendary never checks its PUTs; a dropped upload must not become a recorded sync. The DST-shifted manifest names are not evidence, only a new manifest or the exact same-second name is.
- **The cloud's previous save is not backed up before an upload**: uploads never remove manifests, `download-saves` cannot target a Glider folder (always `<install_dir>/.saves`), and `sync-saves --save-path` rewrites `installed.json`; a local copy of what was uploaded is kept instead.
- **`--force-upload`/`--force-download` follow Glider's own decision**: they are sent only after the 3-way check proved the overwritten side unchanged (or the user chose in resolve/explicit sync); without them Legendary's clock guess could skip or reverse the direction Glider verified.
- **First-time save-folder setup is not a visible writer job**: it only runs when no writer job is running (`Jobs.IsBusy` false) with Legendary's installed-data lock as the backstop, and a pre-launch/after-exit sync that finds the lane busy is skipped quietly; a new `JobKind` would show a flash entry in the queue and touch the engine's job code. `ServiceContext.WhenSavesIdle` makes writer jobs wait for a running sync of their game.
- **A failed or slow sync never blocks play**: only a conflict stops a launch; offline, unreachable Epic, a failed sync or the 60 s budget start the game with the save on this PC and a quiet note or warning.
- **Backups keep 10 overwritten + 5 uploaded copies, 4 GiB per game, and refuse saves over 1 GiB**: the overwritten ones rescue progress, so upload copies and old ones go first; a save too big to copy is never overwritten automatically.
- **EOS overlay on/off is Glider's own HKCU write behind `IOverlayRegistry`, never `legendary eos-overlay disable/enable`**: Legendary's `disable` also deletes HKLM values and dies with a PermissionError without admin rights; the HKCU entries are all a per-user switch needs, and a fake registry keeps tests off the real one. Machine-wide (HKLM) EOS layers are left alone and the state's `Note` says so.
- **Overlay state is read from `overlay_install.json`, `overlay_version.json`, the registry interface and Epic's Program Files folders, never by spawning Legendary; `Installed` = Glider's own managed copy**: an overlay found at EGL's/EOS helper's folder is `ExternalPath` and can be switched on without a download (`overlay.setEnabled`), while `overlay.install` always downloads Glider's copy (EGL's folder vanishes when EGL is uninstalled; Glider can't update it).
- **Overlay install/update is a writer-lane `Overlay` job (anonymous session, no pre-download phase, waits while any game runs); remove runs inline**: the DLL is loaded into running games; remove has no shared state with other writer jobs and the RPC returns the final state. Success is decided by `overlay_install.json`, not exit text, because `remove` can trip over HKLM after the work is done.
- **An overlay update re-switches the overlay off if the user had it off**: Legendary's `update` writes the registry entries again; the user's choice wins. Remove restores Epic's own overlay if HKCU pointed there before.
- **Overlay update check = Legendary's own login side effect**: `overlay_version.json` is refreshed by every login (24 h cache), so the periodic check only re-reads files every 30 min and runs `list-installed --check-updates` on the metadata lane when the cache is over 25 h old; one notice per new version, no auto-update.
- **Prerequisites run elevated at first launch (or `game.installPrerequisites`), not right after install**: a UAC prompt in an unattended post-install hook would hang the writer lane. Ids are remembered in `state/prereqs.json` across games and updates (Legendary forgets them on every update); installer must stay inside the game folder, exist and carry a valid Authenticode signature from any publisher (redistributables are not Epic-signed); exit 0/3010/1641/1638 count as installed.
- **A failed prerequisite stops that launch with `PrerequisiteFailed` + Retry; `game.skipPrerequisites` ("Play anyway") stops asking until the user installs on purpose**: never block a game forever, never nag. Skip is a separate RPC because a new required `LaunchRequest` field would break every existing TS call site.
- **Third-party games are either managed externally (no Epic files: URI hand-off) or linked (`partnerLinkType=ubisoft`, normal launch)**: Legendary's `launch --ubisoft/--origin` only accepts `ThirdPartyManagedApp` games. Hand-off = `launch <app> --ubisoft|--origin --json`, scheme-checked (`uplay://`, `link2ea://`) and opened through `IHostPlatform.OpenThirdPartyUri` (the host's `OpenUrl` only allows http(s)); the link carries an exchange code and is never logged.
- **Ubisoft "activated" = Glider ran `activate --uplay -y` for this account (`state/thirdparty.json`); Play returns `NeedsActivation` until then**: Legendary can't report redeemed keys without doing the work, so one extra click once per account. EA is never gated and never uses `activate --origin` (it always prompts, ignoring `-y`): the EA app asks to activate when it opens the link.
- **Third-party sessions are `Untracked` and shown as "Launching" for a few seconds only**: Glider can't see the game exit, and a session that never ends would pause the download queue for good; no playtime is recorded for them.
- **Missing launcher = registry URL handler absent or pointing at a missing exe**: a managed game is refused with a message naming the launcher; a linked game still starts with a hint in `LaunchResult.Message`.
- **Art lives behind `https://art.glider/{app}/{tall|tall-thumb|wide|logo}?v={hash}` and summaries carry only these short URLs**: `v` = first 10 hex of SHA-256 of the Epic source URL, so art changes = new URL = new immutable cache entry, a disk hit needs no catalog, and 500 games stay ~560 KiB instead of carrying Epic URLs.
- **`art.glider` is served by `WebResourceRequested`, not a virtual-host mapping**: mapped hosts never raise the event (see host.md); the handler takes a deferral, asks Core's `ArtCache`, and answers 404/400 at once for anything unservable so a tile never hangs.
- **Thumbnails are JPEG, sized by Epic's CDN, not by us**: `?w=<n>&resize=1&quality=medium` (verified with curl: 525 KB original → 22-36 KB at 300 px; without `resize=1` the size is ignored; the CDN returns JPEG even for `Accept: image/webp`), and no dependency-free WebP encoder exists in .NET/WPF/WIC, so WebP is not worth a native dependency; logos are stored as delivered (often transparent PNG). Sizes: thumb 300, tall 600, wide 1280 px, never above the key image's own width.
- **Non-Epic sources and v0.1 files are shrunk by the host's WPF codecs when present (`IImageProcessor`)**: Core stays dependency-free; the same decoder gives the cover colour. v0.1's full-size `cache/art/<sha16>.jpg` files are adopted (copied to the new layout) instead of downloaded again and are never deleted (downgrade safety).
- **`GameArt.Placeholder` is a flat colour (≤ 7 chars), not a data-URI**: 500 inline images would add ~400 KB to every `library.get`; the colour is the mean of the cover softened into a calm range (`PixelMath`), kept in `cache/art/placeholders.json` and `cache/library.json`, valid only while the source hash matches, and published to the library at most every 3 s.
- **Art fetching is fenced**: https only, public DNS hosts (no IP literals, localhost, `.local`, credentials, ports), redirects followed by hand (≤ 3, each hop re-checked), ≤ 8 MB, body must sniff as JPEG/PNG/WebP; 6 parallel downloads, one per file, failures remembered 30 s, offline = 404 without touching the network, LRU trim to 90 % of a 384 MB cap by file mtime (touched on a hit at most every 6 h).
- **`FixAction.Update` is the one-click action of an Ask-policy update notice**: additive contract change; the UI runs `game.update` for the notice's AppName. Ask raises one notice + toast per version and the ledger survives restarts (`cache/update-notices.json`), so ten Ask games don't toast ten times at every launch.
- **Always + only-when-idle is retried by a timer (60 s) that exists only while something is waiting, plus at every session end**: the old code tried once per library change and could wait 30 min after the user went idle. Never = badge only and still counts in `LibraryStatus.UpdatesAvailable`.
- **The update check interval is re-read when settings change, backs off to 5 min offline and is skipped when nothing is installed**: the timer is `Task.Delay` on the injected clock against the last check, so it is testable with manual time and costs no wakeups.
- **Update download sizes stay lazy and are also requested when a game's detail is opened**: one dry run per installed/latest pair on the metadata lane, never while the writer lane is busy.
- **The host warms the JSON contract on a pool thread while WebView2 starts (`GliderServiceOptions.WarmSerializers`, host only)**: the first `app.getSnapshot` (145 → ~3 ms in Core) and `library.get` (179 → ~22 ms for 500 games) gate the first paint; measured in docs/perf.md. A pre-serialized blob for `library.get` was rejected: warm serialization of 561 KiB is ~6 ms.
- **Store tab = a second WebView2 child of the main HWND over an HTML placeholder, same environment and `GliderEpic` profile as sign-in, default Edge UA**: no new browser process group, one wipe point (`ClearLoginSessionAsync` destroys the Store first), and Epic's page stays in plain web-checkout mode (no `window.ue` bridge to implement).
- **The Store never gets a channel into Glider**: web messages and host objects off, no virtual host mappings, no injected scripts; the UI only sends a typed `StoreTarget`, Core builds the URL (`StoreUrls`, validated slug + locale), and the host re-checks every navigation with the Core-side `StoreNavigationPolicy` (https + Epic hosts; payment hosts only while a checkout is active; foreign links open in the system browser only on a click).
- **`StoreNavigationPolicy`, `StoreUrls` and `EpicLauncherUri` live in Core, not the host**: they are the security boundary, so they are pure, cross-platform and table-tested; the WPF host has no test project.
- **`com.epicgames.launcher://` is handled in `NavigationStarting`, `LaunchingExternalUriScheme` and `NewWindowRequested`, de-duplicated for 2 s in Core**: which one fires for the web Store's buttons is unverified (checklist L3), so all three cancel and report; any other external scheme is always cancelled.
- **Launcher links only yield an app name, namespace and catalog id (never args, env, paths); `Launch` needs a user gesture on an Epic origin, `Install/Verify/Update` only open the game page, `Uninstall` is ignored**: a web page must not start a game with its own arguments or a download/removal by itself.
- **Store sign-in = cookie probe (names only) then one `/id/exchange` SSO from `legendary get-token --json`, max twice per run, code kept in memory and never logged**: launcher-mode login may not leave a web session; the probe only decides whether to try SSO, a login page after two attempts becomes the `signedOut` state with a retry.
- **`get-token` runs in the metadata lane with sensitive stdout and is rate-limited to one per 10 s**: Epic throttles the exchange endpoint and the code is a credential (`--bearer` is never used).
- **The native view is hidden until `DOMContentLoaded` and while an HTML modal is open (a PNG snapshot stands in for it)**: the HTML placeholder can then draw opening/offline/error states, and Radix dialogs/menus (watched by role in the page) are not painted underneath a native window.
- **New purchases are never detected from the page**: a checkout URL (payment iframe or `/purchase` path) only sets a flag; leaving the tab, re-activating the window and a bounded 20 s/5 min poll refresh the library (single-flight, ≥10 s apart) and an added game becomes a "was added to your library" notice.
- **Free games come from Core's own fetch of the public promotions feed and are re-parsed against "now" on every read**: the strip flips at the Thursday boundary even offline; only 0 %-price windows count (20/35/55/70 are discounts), slugs and art URLs are validated, art is cached under `cache/free-games` and served from `cache.glider`.
- **Store region/locale default from the OS region and UI culture; there is no "Store region" setting yet**: the contract has no field for it (additive later); claiming depends on the account's region anyway.
- **`StoreTarget` routes are `store/product/<slug>`, `store/bundle/<slug>`, `store/free-games`, `store/wishlist`, `store/browse`**: UI-1 links "Free this week" items with `storeRoute({kind:"product", slug})`; the route never carries a URL.
- **One Epic-link parser (`EpicLauncherUri` → `EpicLink`) serves both the OS protocol handler and in-Store deep links; the stricter rule of the two applies**: ASCII only, tokens `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`, slugs only via `StoreSlug` (`[a-z0-9-]`, lower-cased, `/home` tolerated), an undecodable query refuses the link, an unknown `action` yields `Unknown` (no app name), `silent` only as `true`, `library/extra` is `Unknown`, extra `store/p/<slug>/…` segments are `Unknown`; `installer*` stays a prefix (documented whitelist). Uninstall is parsed (so it can be logged) but never acted on.
- **One UI route scheme for the Store: the route carries the typed target; `store/p/<slug>` is only an alias**: `openStore(target)` navigates to `storeRoute(target)` (no separate pending-target store); `GliderLink.Route` emits `store/product/<slug>`; `glider://store/p/<slug>` and Epic `store/p|product/<slug>` links both land there. Bundle pages from an Epic link reach the UI only through the in-Store router (`store/bundle/<slug>`); the protocol handler sends them to the Store's home.
- **Download modes are applied per process by PID, live, with no restart**: Balanced lowers CPU, I/O and memory priority on the file writer only (the DLManager's last child, found from its printed pid and its `workers + 1` direct children) so the network side matches Full; Background idles the whole tree (idle CPU, very-low I/O and memory priority, EcoQoS, 4 workers); the job object no longer pins a priority class in mode-aware runs because Windows forbids raising a process again under that limit.
- **Mode, idle full speed, WhilePlaying Throttle and the speed limit reach the running job through `RunControl`**: the queue pushes the effective mode on every settings/session change and every 5 s (idle has no event); every knob is a priority or a throttle, so changing mode never restarts a download (a restart throws away a partial 4 GiB file plus the cache).
- **16 workers and 1 GiB shared memory on every machine (12 workers under 4 GiB RAM)**: workers wait on sockets, not CPU; 8 reach the ceiling on a good link, 16 on a lossy one, more is slightly worse (docs/download-perf.md 5.3, 5.5).
- **CDN probe is sequential per host, not parallel**: parallel probes split the link and bias the comparison (download-perf.md 5.1); each host costs ~0.3 s. A host is bad on failure, TTFB > 250 ms or < 50 % of the best MB/s; the pick is the first non-bad host in Epic's order, not the fastest (the probe cannot rank good hosts, +-50 % between rounds). Needs a cached manifest (updates, repairs, re-installs); a first install starts on Epic's default CDN.
- **CDN failover on the stock exe = one restart with resume**: after 3 minutes below 40 % of the probe rate while not disk-bound with > 3 GB left, or on a stall that is not disk-bound; at most once per job. The fork switches in place through the control file instead.
- **Disk-bound = shared-memory cache >= 85 % full for >= 10 of the last 15 s**: a full cache is never blamed on the CDN; the limiter names the drive and what the connection could do, and the write speed seen is remembered per drive (`cache/drive-speeds.json`) so the install picker can warn before the next install.
- **Speed limit = worker throttling, not a Job Object net-rate limit**: measured here, a job capped at 5 MB/s still downloaded at 31 MB/s (the limit shapes outgoing traffic only). The stock exe is throttled by duty-cycle suspension of the download workers (250 ms period, feedback on Legendary's raw rate); the fork by `max_active` in the control file (AIMD).
- **The Glider fork of Legendary stays inert until its CI release exists**: the workflow, pin, patch hash, source offer and fetch/smoke/build switches are in the repo and the recipe was built and smoke-tested locally, but a PyInstaller hash is not reproducible across machines, so `build/legendary.json` keeps the stock exe until the workflow has published a release.
- **The Glider fork of Legendary (0.21.1-glider.1) is the pinned exe now**: control file, CDN failover and speed limit in place and clearer progress need it (docs/download-perf.md 5.4); `build/legendary.json` holds the fork pin (a test ties it to `LegendaryCli.PinnedSha256`), the patch, `SOURCE-OFFER.txt` and the license ship next to the exe and Settings -> About says "modified by Glider".
- **The fork's release is in this private repo, so `FetchLegendary` downloads github.com release assets through the REST API when `GH_TOKEN`/`GITHUB_TOKEN` is set**: release by tag -> asset id -> `Accept: application/octet-stream` with a Bearer header (never printed, dropped on the redirect to storage); no token = anonymous download as before; the exe's SHA-256 is always verified, CI passes `github.token`.
- **Data root = `%LocalAppData%\GliderData`, outside Velopack's install root (schema 3, review H6)**: Velopack's uninstall deletes `%LocalAppData%\Glider`, which held the only copies of save and EGL backups, the save ledger and Legendary's sign-in; a sibling folder needs no new permissions and stays on the same volume, so the move is a rename.
- **The data-root move runs in the host, before Core**: logging, the WebView2 environment and every store open files in the root; it runs right after the single-instance mutex is taken (old builds use the same mutex), and an explicit `--data-dir` is never moved.
- **One rename per directory, put everything back on a lock**: a directory rename is atomic and Windows refuses it while a file inside is open, so nothing is half moved; Glider never runs on a split root (rollback failure = error and exit, the next start resumes).
- **No move journal: the file system is the journal**: before the commit marker a directory reaches the new root only complete, so "only new" = moved, "both" = verified copy, `.moving\` = discard; this makes a crash after any step resumable and is tested step by step.
- **Cross-volume = copy, verify (sizes; SHA-256 for state and backups), rename into place, delete the source only after the marker**: the only case is a junctioned folder; the uninstall hook allows renames only.
- **Move first, then convert v0.1 → 2 in the new root, then mark schema 3**: the move must precede everything that opens the root and the conversion needs Core; the conversion's backup then lands outside the uninstall folder. `schema.json` keeps `migratedFrom` and gains a `history`.
- **The managed EOS overlay moves too, with its absolute paths re-pointed after the commit** (`overlay_install.json`, `jobs.json`, HKCU `OverlayPath`): leaving it behind would make uninstall break the registration; these are Glider's only absolute paths into its own root.
- **A retried v0.1 migration reuses the newest byte-identical backup (review L8)**: a deterministic failure no longer adds a backup folder per start.

## Final UI review fixes (docs/review-v0.2-ui-final.md)
- **Offline holds the queue instead of failing it (M1)**: `QueuePolicy.HoldReason` is "Waiting for an internet connection" while Core is offline and wins over the while-playing hold; it applies to the same kinds a game's hold does (everything `JobPlan.CanPause`: install/update/repair/verify/import/modify; uninstall and move still run), so a verify or import waits too rather than being split by whether it happens to need Epic.
- **A `network` failure marks Core offline (`ReportOffline`), a `cdnUnavailable` one does not**: a job that cannot reach Epic at all is the earliest, surest sign of an outage (the library sync may not run for hours), and without it nothing ever flips the state, so the hold and the resume would never fire; Epic's servers failing is not this PC being offline.
- **"Epic is back" resumes the outage's casualties: failed jobs with `network`/`cdnUnavailable` whose failure ended within 2 min before the offline spell began or later, at most 3 times each, never while the user has the queue paused**: the 2 min slack covers a download that dies before Glider notices; the cap stops a flapping line looping forever; dismissed jobs are already gone and any other error stays in Couldn't finish for the user.

## Download card, as built (direction D; docs/design-download-card.md §7)
- **Whole-job ETA is two countdowns, the later one wins**: while downloading `EtaSeconds` = max(download countdown, write-tail countdown) (the writer runs beside the network and on a slow drive finishes long after it), while installing it is the write-tail countdown instead of `null`, every other phase keeps its own estimate. The write tail is a countdown in `ProgressSmoother` (same predicted-minus-dt-then-ease correction as the download's), so it never jitters; without the writer's total it falls back to the download's value (null while installing, as before). The planned verify step is not added: its own ETA takes over when it starts.
- **`NetworkStats.CeilingBytesPerSecond` is nullable and shares `LimiterDecision.Ceiling`** (max of the job's peak and the CDN probe, null until either exists), so the number on the chart's dashed line and the one in the limiter's sentence cannot differ.
- **`QueueState.Hold` is `HoldInfo(kind game|offline|egl|paused|other, subject)` beside the string**: a paused queue wins, then offline, then a game under "While a game is running: Pause" (subject = its title), then whatever the head `waiting` job says. `Holds.FromBlockedReason` reads Core's own sentences once (game to close / paused while running, internet connection, Epic Games Launcher) and keeps any other sentence as `other` + its text, so the card never parses text; `QueueState.HoldReason` is unchanged.
- **A held job reads as waiting from the queue's hold, whatever Core calls it**: the card treats `queued` and `waiting` jobs under a hold as held ("Waiting for Fortnite to close"); a user pause wins over a hold; a `queued` job with no hold is "Starting…"; a `waiting` one with no hold shows Core's sentence.
- **Paused time is one phrase: "{Downloading paused} · 659 MB of 1.5 GB · 1 min left when you resume"** ("Under a minute left when you resume", never "about under a minute"). Core clears `EtaSeconds` while paused, so the card derives it from the job's averages (the later of download and writes owed); with no averages the phrase is simply left out. Paused step names are phrases ("Install paused", "File check paused"), not "Checking files paused".
- **Time-phrase audit**: headline "N min left" (digits big, "min left" quiet), "Under a minute left", paused/held lead in words with no time, `Almost done` / `Preparing…` / `Removing files…` for steps with nothing to count, no elapsed, no averages, no "about" anywhere on the card; a unit test greps every state's text for stacked qualifiers.
- **A hold's line puts the bytes first**: "15.8 of 37.6 GB · Downloads pause while you play and continue on their own" (no period between), and a lone sentence keeps its period; the spec's "sentence. · bytes" read as two sentences glued together. The Epic-launcher line says "installing" or "updating" from Core's reason; a hold of kind `other` leads with Core's own sentence.
- **Pause is offered on held work only once it has started** (spec); a held job that never started shows just Cancel. Resume is the same dark glass square as Pause with a play glyph and the accessible name "Resume" (no white fill), so the band never carries a bright primary while a download is in progress. The one labelled primary is Ready's Play (§7.2: the payoff, not a pause state).
- **Focus ring over art is an outline plus a dark halo (`[data-band] :focus-visible`: 2 px accent at 1 px offset, `0 0 0 5px rgb(0 0 0 / .8)`)**: at the suggested .55 the halo over flat white measured 2.1:1 against the ring (2.5:1 on bright art), at .8 about 4:1; `focus.spec.ts` measures the ring against its halo (≥ 3:1) on green, purple, blue, white, bright and busy art in both themes.
- **Details stays as the player left it** (`localStorage` `glider.downloads.details`, every access wrapped, the card works without it); it is closed on a first visit. The chart is mounted and subscribed only while Details is open.
- **Ready lives in the page, not Core**: a job of kind install, update, repair, verify, move or modify that completes while Downloads is open keeps the card ("Ready to play" + labelled Play for install/update; "All files are fine" / "Repaired N files" / "Moved to E:" without Play) until the next job becomes current, the page is left, `READY_MS` (10 min; the spec names no timeout, this only stops a stale card sitting there all day) passes, or History is cleared; while it shows its row is left out of History. A job that finished while the page was closed goes straight to History.
- **Holds are said once, on the card**: the page notice is now only for a queue the player paused ("Downloads are paused. Resume all"); the offline and game wording and the Change link moved into the card (Details → "While a game is running · Pause downloads · Change").
- **Screen readers**: the card is a labelled region (the title is its `h2`); one polite status is recomposed only when the step, a 10 % step, a hold, a pause or the cause changes and then carries the time left ("Downloading Fortnite, 30 percent, 7 minutes left. Limited by drive D:."), never at tick rate; the bar's value text is "33 percent, 1 hour 37 minutes left" and the visible percent stays `aria-hidden`; Ready is announced once after mount.
- **`ProgressBar` gained `valueLabel` and a 200 ms background-colour transition and no longer desaturates the neutral tone; the sheen cadence is unchanged** (the spec's calmer 1.6 s-every-6 s sheen would also change the game hero's and the Home strip's bars, which this task doesn't touch).
- **Chart**: `ThroughputChart` takes `ceiling` and `ceilingLabel` (dashed line, y-axis always reaches it); the card draws it only while a cause is shown and only for the download series. `PhaseStepper`, `SpeedStatus` (and its dialog), `figuresOf`, `timeOf`, `stateOf`, `metaOf`, `explainSpeed` and the card's `compact` variant are deleted; `JobSparkline` moved to its own file; `ThroughputChart`'s average/peak/legend options stay (its tests and the sparkline family still use them).
